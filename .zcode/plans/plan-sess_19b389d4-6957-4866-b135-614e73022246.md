## 背景

管理后台「积分定价 → 按规格定价」中，价格档的"生成时长"目前是一个下拉框，只能从模型能力展开的每一秒里单选（`selector.videoSeconds` 精确字符串匹配，`0`=任意时长）。像"5 秒、8 秒、10 秒同价"的模型必须建 3 个档位，维护成本高。

目标：时长条件支持**闭区间范围**（如 5–10 秒），请求时长落在区间内即命中该档；保留"任意时长"兜底档；最短=最长时等价于固定秒数。存量精确档完全兼容。

**核心设计**：扩展 SKU 选择器协议中 `videoSeconds` 的取值格式：`"N"`（精确，存量不变）| `"N-M"`（闭区间，新增）| 缺省/`"0"`（任意时长）。数据仍存在 `selector_json` 文本列（`channel_model_price_tiers` 表），`selector_key` 唯一索引天然区分不同区间，**无需数据库迁移**；旧列 `VideoSeconds` 存区间下限，仅作旧逻辑回显兜底。

## 后端（backend/）

1. `internal/app/channel_models_pricing.go`
   - 新增 `parseVideoSecondsSelector(value string) (min, max int, ok bool)`：解析 `"N"` / `"N-M"`。
   - `normalizeChannelModelTierSelector` 的 `case "videoSeconds"`：接受 `N` 或 `N-M`（要求 `0 < N <= M`，`N-N` 归一化为 `"N"`），非法值报错"视频价格档时长必须是非负整数或 N-M 区间"。
   - 结尾派生旧列 `VideoSeconds` = 区间下限（现在 `strconv.Atoi` 遇 `"5-10"` 会得 0，必须改）。
   - `validateChannelModelTierCapabilities`：区间档改为校验"范围与模型支持时长集合有交集"——enum：至少覆盖一个枚举值；range：与 `[Min,Max]` 存在 step 对齐的交集（算术计算，不做大范围展开）。精确档校验保持现状。
   - `normalizeChannelModelPriceTiersWithIDs`：新增同优先级时长区间重叠校验——两个档选择器键集合相同且非时长条件全部相等时，时长约束（精确或区间）不得相交，否则报"价格档 i 与 j 的时长范围重叠"。与前端 `priceSelectorIssues` 同口径。
2. `internal/app/model_router.go`
   - `matchSKUSelector`：`key == "videoSeconds"` 且期望值为区间时，请求值按数字判 `∈ [min,max]`；其余键保持精确比较（1.5K 邻档特例不动）。
   - `channelModelHasCompatiblePriceTier`：已提供的 `videoSeconds` 对区间档同样按数值区间判断。
3. `internal/app/logical_models.go`
   - `capabilitySpecWithPriceTiers`（L676-733）：时长约束不再直接收集 `tier.VideoSeconds`，改为——任一活动档不约束时长则保持原 spec；否则取能力声明候选时长（`spec.Options["videoSeconds"]` 的 `Values`，或 numeric Min/Max/Step 按 step 展开，设合理上限防超大展开），过滤出被任一档（精确相等或落在区间）覆盖的值写入 `Values`。
   - `channelModelDefaultOptions` 回退（L765-778）：区间档下限可能不对齐 step，改为取第一个"能力支持且被该档覆盖"的时长作为默认，而不是直接用 `tier.VideoSeconds`。
4. 测试：在 `internal/app/channel_model_pricing_test.go` 等补充：区间规范化/非法值、`matchSKUSelector` 区间命中与不命中、区间重叠拒绝、能力校验交集判断、`capabilitySpecWithPriceTiers` 覆盖过滤。运行 `go test ./internal/app/`。

10. `components/model-picker.tsx` + `components/admin` 下 `channel-model-cost-summary.tsx`：档位时长标签支持区间显示（`selector.videoSeconds` 优先，显示"5–10 秒"；否则回退旧列），保持"全部时长"文案。

## 前端用户侧

11. `lib/model-pricing.ts`：`priceTiersForCurrentSelection` 的条件比较（`requested[key] !== value`）对 `key === "videoSeconds"` 且档位值为区间的情形按数值区间判断，保证本地估价与模型菜单按已选时长命中区间档；`priceSelectorForTier` 不变（selector 原样携带 `"5-10"`）。
12. `services/api/wallet.ts`：`ChannelModelPriceTier.selector` 注释补充区间格式；`docs/content/docs/backend/backend-database.mdx` 中 `channel_model_price_tiers` 行补充说明 selector 支持 `videoSeconds: "min-max"`。

## 验证

- 后端：`cd backend && go test ./internal/app/`（先跑定价相关专项，再全量）。
- 前端：`cd web && bun run build`；`bun test channel-model` 若存在相关测试。
- 手工冒烟（如用户要求）：启动前后端，在管理端建一个 5–10 秒按秒计费档，确认创作端 5–10 秒任意时长命中该档、区间外提示无价格。

## 明确不做

- 不改表结构与迁移（selector_json 文本列直接容纳区间）。
- 不引入开区间语法（≤X 用能力上限作 max，≥X 用能力下限作 min 表达）。
- 定价模板「规格定价」仍按枚举值生成精确档，区间由管理员手工编辑。
